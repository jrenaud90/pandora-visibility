# v1.4.0 (2026-08-28)
- Added `get_best_roll`, the best single roll held over every timestep it is given: the roll with the most timesteps where the boresight keep-outs and the star trackers pass, ties going to the highest mean solar power. `get_visibility_best_roll` makes that same choice once per orbit window and may change roll between orbits; an observation that must hold one attitude across several orbits (the short-term scheduler's one-roll-per-target-per-visit rule) calls this instead.
    - `min_power_frac` drops rolls whose mean solar power over the timesteps is below it before the search. A floor no roll reaches is ignored rather than leaving the attitude undefined.
    - `weights` gives each timestep a weight in the count. Integer weights keep the count exact, so a caller can rank one group of timesteps strictly first (weight larger than the other group's total) and let the other group break ties.
    - When no roll observes a single timestep, or the tracker keep-outs are off, the roll best for the trackers alone and then the best-lit roll are returned in turn, with `n_visible` saying whether anything is observed, so the caller always has an attitude.
    - Returns `visible`, `boresight_visible`, `n_st_pass` and `solar_power_frac` per timestep at the chosen roll, the same quantities `get_visibility_best_roll` reports.
- `get_visibility_best_roll` and `get_orbit_roll_angles` now run on the same private search as `get_best_roll` (`_best_roll`), once per orbit window, so the three cannot drift apart. Their outputs are unchanged; checked bit for bit against v1.3.0 across nine keep-out configurations, six targets and two time grids. That replaced the single-roll star tracker evaluation `get_visibility_best_roll` restated inline, and `_pick_orbit_roll` became `_pick_roll`, which returns the winning row and takes the weights.

# v1.3.0 (2026-08-27)
- The constraint diagnostics can now reproduce a `get_visibility_best_roll` run. `get_all_constraints` and `get_star_tracker_constraint` take a `roll` argument, and the new `get_orbit_roll_angles` reports the roll held during each orbit. Passing one to the other makes the per-constraint verdicts agree with `visible` step for step.
    - Fixes the star tracker constraint disagreeing with the visibility result it was meant to explain. The diagnostics evaluated the trackers at the default Sun-constrained attitude, recomputed every step, while `get_visibility_best_roll` holds a single roll for a whole orbit.
    - `get_orbit_roll_angles` sweeps for a roll whether or not the boresight is clear, so a diagnostic can still say which star tracker would have failed on an orbit the boresight had already lost. `get_visibility_best_roll` keeps skipping that sweep, since it would be searching for a roll it could never use, and its outputs are unchanged.
    - A `roll` given to `get_visibility`, `get_all_constraints`, `get_star_tracker_constraint` or `get_star_tracker_breakdown` may now be an array holding one angle per timestep, not only a scalar.
    - The per-orbit boresight check and roll sweep moved into `_boresight_ok`, `_orbit_roll_sweep` and `_pick_orbit_roll`, shared by both roll searches so they cannot drift apart. That also replaces the three copies of the boresight keep-out check inside `get_visibility_best_roll` with one.
- `summary()` no longer contradicts itself in its star tracker section. It built the per-tracker rows from `get_star_tracker_angles` while the `Result` line came from `get_star_tracker_constraint`, and the two measured the Earth limb differently, so a step could print both trackers failing above a passing result. Rows and result now both come from `get_star_tracker_breakdown`, which shares its geometry with the check itself.
    - `get_star_tracker_angles` reports the geocentric limb angle the constraint applies, rather than an AltAz altitude referenced to the geodetic horizon. Reported angles move by up to 0.2 deg and now match the value the keep-out is tested against.
    - Removed `_get_angle_from_earth_limb`, which had no callers left.
- Fixed a keep-out set on one star tracker alone having no effect. `st_required=1` ORed the two tracker verdicts, and a tracker with no keep-outs passes by default, so `st1_earthlimb_min=30*u.deg` on its own was waived by the unconstrained ST2 and rejected nothing. Over a day at 1 minute cadence that config passed 100% of steps, where the same limit applied to both trackers passed 79%. It now passes 46%.
    - `st_required` counts only trackers carrying an active keep-out. Nothing changes when both are constrained, and nothing changes for `st_required=2` either, since ANDing against an always-passing tracker already reduced to the constrained one.
    - `n_st_pass` from `get_visibility_best_roll` likewise counts only the constrained trackers, rather than scoring one that was never asked as a pass.
    - The reduction moved into `_combine_tracker_results`, the single place `st_required` is now applied, shared by the constraint check, the breakdown and both roll searches.
- The class defaults now match what is currently being used on flight.
    - The dynamic wedge takes precedence over the day/night pair, so `earthlimb_day_min` and `earthlimb_night_min` are the fallback for `use_dynamic_earthlimb=False` rather than the thresholds actually applied on the defaults.
    - Star tracker keep-outs being on by default means `get_visibility` evaluates the tracker geometry for every caller, and `get_visibility_best_roll` sweeps for a roll, where both previously skipped that work.
- `daynight_mode` now sets the Earth reference point for the dynamic DPC wedge as well as the day/night step pair. It previously applied only to the step pair: the wedge always measured the illumination angle at the nearest limb point and silently ignored the setting, so `daynight_mode` and `use_dynamic_earthlimb` together could not express a subsatellite-referenced wedge. Both Earth limb models now read the same point.
- The default `daynight_mode` is now `"subsatellite"` to match DPC's reference point. Meaning the solar zenith angle on the ground directly below the spacecraft, which is independent of where the boresight points. Set `daynight_mode="limb"` to reference the patch of Earth the boresight actually grazes instead. The two references sit ~22-26 deg of geocentric arc apart at Pandora's altitude, so they can disagree about illumination near the terminator.
- `repr()` now reports a non-default `daynight_mode` on the dynamic branch too, where it was previously omitted because the setting had no effect there.

# v1.2.0 (2026-08-12)

- Added `use_dynamic_earthlimb` (default True) to `Visibility`. When True the boresight Earth limb keep-out follows the piecewise DPC wedge curve as a function of the Earth illumination angle at the nearest limb point, instead of the fixed day/night limb limits. Star tracker keep-outs are unaffected.
    - Changed the default `daynight_mode` from `"subsatellite"` to `"limb"`. This changes results for any run that sets `earthlimb_day_min` or `earthlimb_night_min` without naming a mode. 
    - Fixed `summary()` reporting the wrong Earth limb threshold. It derived day/night from the nearest limb point regardless of `daynight_mode`.
- Added a easy to use target visibility notebook ("target_visibility.ipynb") which can accept multiple targets including just names of targets.
    - The target visibility notebook accepts planet names ending in a lowercase letter ("TRAPPIST-1 b", "WASP-160 B b"). Their ephemerides are pulled from the NASA Exoplanet Archive, and transits (blue) and secondary eclipses (purple) are overlaid on the visibility timeline with the observable fraction of each event reported. Unresolvable stars, unknown planets and non-transiting planets each raise a warning and degrade gracefully.
- `get_all_constraints`, `get_constraint`, `get_separations`, `get_star_tracker_constraint` and `summary` now run off the same precomputed data as `get_visibility` instead of doing their own per-body ephemeris and coordinate transforms.
- Fixed the diagnostic API disagreeing with `get_visibility`. It used astropy's `separation`/`AltAz` while `get_visibility` used direct vectors, so a step could be reported not visible with no constraint failing. Note that `get_separations["earthlimb"]` was an AltAz altitude, referenced to the geodetic horizon, added to a geocentric limb half-angle; it is now geocentric throughout, which shifts reported limb angles by up to 0.1 deg and matches the value the constraint is actually applied to.
- `get_visibility_best_roll` is much faster. The orbit sampling grids and their ephemeris are now built in one vectorized pass instead of two astropy calls per orbit, cached and shared between every target on the same time grid; the roll sweep runs over all roll angles at once; and the per-orbit target transform is done once for all orbits. Visibility, roll and star tracker results are unchanged. Measured on 5 targets over 14 days at 10 minute cadence: 87 s to 9.5 s.
    - Added the `ephemeris_step` option to `Visibility` (default None, i.e. unchanged behavior). Set it to a time Quantity (e.g. `60*u.min`) and the Sun and Moon are evaluated on a grid of that spacing and interpolated, taking the same 5-target run to 2.4 s. Only the smooth geocentric body motion is interpolated, the spacecraft's own position is always exact, so directions stay accurate to better than 0.01 deg.
    - Fixed the `_precompute` cache keying on `id(time)`, which could serve another time grid's data if a recycled object address happened to match.
- Added `get_star_tracker_breakdown`, which reports which star tracker fails which keep-out per timestep, with the separations and limits behind each. It shares its geometry with the constraint check itself, so the per-check masks always reconstruct the verdict.
